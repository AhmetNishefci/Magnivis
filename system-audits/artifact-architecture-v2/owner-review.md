# Artifact Architecture V2 — owner review

Duplication originated in the native portable delivery generator (video/cover copy per platform), repeated generation into review/release roots and durable registration of each package file set. Audit: 442 media paths, 366 unique payloads, 426,582,475 redundant checkout bytes. Git already shares identical blob storage. No binary was deleted/moved/changed; immediate storage saving is zero.

Selected architecture: prospective SHA-256-bound MediaArtifact catalog; native PlatformVariants optionally bind exact canonical media (required for new V3 durable delivery); Delivery Manifest V3 references video/cover instead of copying. Existing generator and validator retain all source/editorial/readiness/profile/media checks. The manual resolver prints the canonical upload file. Arbitrary platform-specific payloads and shared transformed payloads remain supported, with independent presentation gates. State changes and publication authority are records, not payload copies.

Historical strategy B freezes 948 checkpoint files, including all approved/candidate/media/audio/cover/delivery/authorization/QA/recovery snapshots. Original candidate/locked-master identities and legacy V1/V2 package hashes remain valid. The missing original Wood Frog expectation is preserved. Documentation updates are exact before/after hash-bound amendments, with original authority snapshots; no narrator/creative/cadence/discovery policy changes.

The catalog indexes existing bytes at their existing meaningful canonical paths. IDs are `media.<SHA-256>`; ordinary duplicate hash registration fails. Identity/path/hash/size/provenance and generation parent references are immutable. A separately retained same-byte evidence snapshot or compatibility copy requires a reason and hash-bound decision plus duplicateOf, not a platform/lifecycle convenience exemption. No garbage collection is introduced.

PublicationMediaAuthorization binds owner decision, exact variant revision/hash, ready manifest hash and media identity without copying. Native PublicationRecord can reference the exact uploaded MediaArtifact; registry and published-media checks reject mismatches. No new authorization or completed publication/metric record was created by this milestone.

Chocolate scheduling is recorded solely as owner-reported manually scheduled on four platforms. Exact date/time remains null; 20:00 Kosovo is only a provisional strategy window. Existing release authorization and exact 3491a81c… master remain unchanged. No inferred URLs, IDs, success, device/UI observations or analytics.

Changed areas: src/artifacts/media.ts + artifacts/media-catalog.json; native platform/delivery/operations schemas and platform/operations registries; existing delivery generator/validator and CLI resolution; publication/media binding helpers; artifact status/durability/check gates; scoped historical/authority validators; two new regression suites; append-only scheduling evidence; AGENTS and architecture/artifact/delivery/platform/operations/state/decision docs; bounded system audit/baselines/receipts. No dependency or paid service added.

Validation and clean-checkout results are recorded in validation-results.json, clean-checkout.json and scoped-secret-scan.json. Regression cases cover four-platform shared master, distinct TikTok payload, shared transformed payload, review→ready and authorization without copies, exact published identity, covers, evidence exceptions, frozen history, missing/stale/cyclic/tampered references and arbitrary presentation requirements, renamed duplicate payloads, large unknown-format binaries and approved-master lineage. Synthetic test bytes are explicitly not video/device evidence.

Remaining limitations: legacy duplicate paths remain intentionally; V3 is prospective, so existing owner-approved Chocolate/Longitude variants and delivery JSON were not rewritten. Git-backed canonical paths must be tracked with provenance; this architecture is not a cloud store or guarantee of byte-identical regeneration. Local/platform evidence retains its actual strength, and future variant quality still requires appropriate presentation review. Large Git file policy remains unchanged. No Cycle #4, media generation/modification, upload, scheduling or publishing was performed by Codex.
